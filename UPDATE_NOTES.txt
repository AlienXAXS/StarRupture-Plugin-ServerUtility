Unreleased

- Built-in default rows for host rules: every cheat-style section of BetterCheats (including `stack-size`), Best Builder's six build cheats, CameraControls `vitals` and WaveOptimiser `heat-tools` are denied for players by default. They are part of the plugin, so an existing HostRules.ini gets them, and they apply to remote players on a server only (single player and a listen host's own player see no change). Admins and ExemptRules players are exempt. An exact `[Rules]` line (`BetterCheats.stack-size=allow`) replaces a default; `Plugin.*=allow` and `[Policy] Default=allow` do not open one. A player's `Sections=` key opens a default row only when it names the exact `Plugin.section`; `Plugin.*` does not. `hostrules` lists the default rows marked `(default)`. The in-game admin window (F8, Mods tab) shows such a section as `Deny (default)` until a rule names it; the server sends the default list, and a window talking to a server without it shows none.
- In-game admin: an admin's game with the client file (ServerUtility.dll from the Client Release build, in its Plugins folder) and a mod loader with plugin interface 80 or newer opens a Server Admin window with F8. The admin pairs once with a code from `admin pair <id|number>`. The client ties the pairing to the server address its game connected to, so it pairs again if that address changes or it joins by a different route. Challenges are single use and expire after 30 seconds, so another server cannot replay a paired admin's proof. The client declares plugin interface 80 and does not load on an older loader (the loader's log says why); the server DLL still loads on older loaders. If the loader cannot read the server address on a game build, pairing is refused. Feature titles and mod versions come from the admin's own loader, sent to the server once per proven connection and remembered there.
- New `hostrules known` RCON command: lists the mod features the server has seen players report, and warns about a rule that matches none.
- The in-game admin tool's server half now sends a paired admin the rules, minimums, mods and players, applies the changes the admin makes (with the same checks as RCON), and tells every paired admin to refresh after a change from any source. A change made on out-of-date state is refused and the admin gets the new state. 20 change requests a second per connection at most. Plugin names with single spaces (for example "Best Builder") are carried through unchanged.
- New in-game admin tool, server half: an admin pairs the ServerUtility admin client once, with a one-time code from `admin pair <id|number>` (shown only in the RCON reply, never logged) or, right after claiming admin, on the same connection without a code. After that the client proves a stored secret each session (Plugins\ServerUtility\admin-pairing.txt). `admin unpair <id|number>` or losing the Admin flag removes the pairing. Players without the Admin flag get one "no access" answer and then nothing. `[Policy] InGameAdmin=0` turns it off.
- ServerUtility now takes its game values (function addresses and member offsets) from the mod loader's version object map (the version map), so the same DLL runs on every supported server build. It still carries its own values for CL 127004, the current 0.3.5 server. On any other server build, if the loader has no entry the plugin needs, the plugin is refused and ModLoader.log says why ("will NOT be loaded").
- The auto-profession patch that goes with Max Players now reads the Soldier value from the game's own data instead of a fixed number. If the game build has no such entry, the patch stays off and the log says so.
- The RCON player list now uses the world the mod loader supplies, which stays right after a game update, and is refreshed on the game thread instead of a background thread.
- Building the plain `Debug` or `Release` configuration now stops with a clear error that names the Server configurations, instead of quietly building against the wrong game files.
- Docs now match the code: the admin panel keys are `Enabled`, `ApiKey` and `SessionExpiry` in `[AdminPanel]`, `RemoteVulnerabilityPatch` is in `[PluginSettings]`, `-RconPort` has no default, and `-SessionName` is only needed for command-line server settings.
- The README now says the admin panel is disabled in this build, and that a ban only kicks the player and records their player ID and name in `bans.txt`: nothing reads that file, so they can rejoin.
- New host setting that removes a player whose mod loader, or one of whose mods, is older than a version the host sets (`hostrules minversion`, `hostrules modmin <plugin> <version>`). The player is sent to the main menu with a short written reason. Each player is removed at most once per join. Nothing is removed while both minimums are off. Players with ExemptVersion or Admin in the player list are kept, and players without the mod loader, on a development build, or without the named mod are never removed. Needs mod loader with plugin interface 79 or newer.
- New host player list in the [Players] section of HostRules.ini, by player ID, with the flags Admin, ExemptVersion, ExemptRules and Sections. A player flagged Admin or ExemptVersion is skipped by the version removal. Manage it over RCON: `player [list|ids|set|remove|reload]` and `admin add|remove|clear` (`player ids` shows each connected player's ID). A 1-3 digit argument is the number from `player ids`; anything else is an ID.
- The admin panel gains `/rules/players` and `/players/list` shows each player's ID and list flags. The panel is still off in this build, so RCON is the working path.
- New `hostrules` RCON command and the [Policy], [Rules] and [MinVersions] sections of HostRules.ini: switch a mod's feature off for players (`hostrules deny BetterCheats.movement`, `Plugin.*` for a whole mod), set what a feature with no rule gets (`hostrules default allow|deny`) and the message players see (`hostrules message <text>`). The rules are saved and sent to the mod loader whenever they change. Needs mod loader with plugin interface 79 or newer; older loaders refuse to load it and say a newer loader is needed.
- `hostrules minversion` and `hostrules modmin <plugin> <version>` are saved, sent to the mod loader after every change, and enforced (see above). `hostrules` shows `version minimums: sent` or why they were not sent.
- `hostrules modmin <plugin> wire` is accepted: the copy must pass the mod loader's wire check. `player` and `admin` replies name the player they changed, a Sections key with unsafe characters is refused, and the admin panel's kick, ban and give take an optional `player_id`; without it `player_name` must match exactly one connected player. After editing HostRules.ini by hand, run `player reload` before changing players over RCON or the panel.
- Host rules accept mod names with spaces, such as "Best Builder", in HostRules.ini and over RCON: put the name in double quotes (`hostrules deny "Best Builder.some_feature"`, `hostrules modmin "Best Builder" 1.2.0`). A Sections= key takes the same quotes, around the whole value (`sections="Best Builder.some_feature;Other"`).
- Mod names in host rules now follow the mod loader's naming rule (letters, digits, `_` and `-`, with single spaces between words, up to 64 characters). A row whose name breaks it is logged and ignored.
- `hostrules who <id|number>` shows a connected player's ID, how many times their mod loader reported its features and when it last did, the mod loader version, and each mod's features on or off. A player whose mod loader sent nothing shows `no report (vanilla or older loader)`.
- Admins and ExemptRules players are exempt from the rules: they get a set with nothing denied (the server message still shows). A player with Sections= gets the host's rules with those keys allowed. Edits to the rules or the player list are applied to players already connected.
- New admin claim code: while the player list has no admin, the server log shows a one-time code (and RCON `admin code` prints it). A player with the mod loader is asked for it when they join; typing it right makes them an admin. "Not me" closes the prompt until the server restarts. 5 wrong tries per player stop the asking for that player until restart, and 5 wrong tries in total replace the code. `[Policy] AdminPrompt=0` turns the asking off. Needs a mod loader with plugin interface 79 or newer on the server and the player; vanilla or older-loader players are never asked.
- The admin panel now matches its endpoints when the mod loader adds a trailing `/` to the address, so `/players/list/` and the other calls no longer answer 404. The panel is still off in this build.
- Changes to the host rules and the player list now go through one code path whether they come from RCON or the admin panel: the same checks, one save and one push to players per change, and an audit line in the log. The admin panel gains /rules/catalog, /rules/get, /rules/set, /rules/policy, /rules/minversion and /rules/modmin, and a change may send base_revision so a page that is out of date is refused with 409 instead of overwriting a newer change. RCON replies are unchanged. The panel is still off in this build.
- New remembered feature list: every mod feature a player's mod loader reports is kept in Plugins\ServerUtility\known-features.txt (newest mod version, title, the game builds that reported it off, last seen), so it stays after a restart. `hostrules` shows it with where each row came from and warns about a rule that matches no known feature, and the panel's /rules/catalog returns it as `known`. The file is written at most once every 10 seconds, and only when something changed.
