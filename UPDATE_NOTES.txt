- ServerUtility now takes its game values (function addresses and member offsets) from the mod loader's version object map (the version map), so the same DLL runs on every supported server build. It still carries its own values for CL 127004, the current 0.3.5 server. On any other server build, if the loader has no entry the plugin needs, the plugin is refused and ModLoader.log says why ("will NOT be loaded").
- The auto-profession patch that goes with Max Players now reads the Soldier value from the game's own data instead of a fixed number. If the game build has no such entry, the patch stays off and the log says so.
- The RCON player list now uses the world the mod loader supplies, which stays right after a game update, and is refreshed on the game thread instead of a background thread.
- Building the plain `Debug` or `Release` configuration now stops with a clear error that names the Server configurations, instead of quietly building against the wrong game files.
- Docs now match the code: the admin panel keys are `Enabled`, `ApiKey` and `SessionExpiry` in `[AdminPanel]`, `RemoteVulnerabilityPatch` is in `[PluginSettings]`, `-RconPort` has no default, and `-SessionName` is only needed for command-line server settings.
- The README now says the admin panel is disabled in this build, and that a ban only kicks the player and logs them in `bans.txt`: nothing reads that file, so they can rejoin.
- Groundwork for removing a player whose mod loader is older than a version the host sets: the removal can now send the player to the main menu with a written reason (whether the game displays it is not confirmed yet), and removes each player at most once per join. Exempt players will be skipped once the host's player list exists. Nothing is removed yet. The setting arrives in a later release, together with a mod loader version that reports the player's version; until then the log says the mod loader has no host rules support.
- Needs mod loader v1.25.0 or newer.
